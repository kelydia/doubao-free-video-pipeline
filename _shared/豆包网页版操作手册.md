# 豆包网页版最小 SOP（唯一权威）

> 标准：**简约、直接、稳定**。优先级 **稳定 > 省 token > 省时间**，冲突时按此排序。
> **取舍不预设规则**：遇到「稳 vs 省」的选择（例如多耗一次额度拿真视频 / 0 额度静态补位镜），
> 自动化只准备证据（未完成镜头、失败原因、成本），**交给人工选择**，不自动触发。
> 对应全局 `~/.dsh/AGENTS.md`「任何重跑先说明原因与成本、人工确认后才执行」。
> 实现入口 [`_shared/scripts/doubao_ui.mjs`](scripts/doubao_ui.mjs) 只是校验层的函数；
> 其余 [`工作流_SOP.md`](工作流_SOP.md) / `专题手册/01–05` / [`复盘_2026-11-15.md`](复盘_2026-11-15.md) 都是**按需查的附录**，开工不必通读。

## 一、每次提交前的 5 条确定性校验

| # | 查什么 | 不通过怎么办 |
| --- | --- | --- |
| 1 | 当前是图像还是视频模式（`freshChat` 不切模式，会残留） | 显式切模式并复判一次，不猜 |
| 2 | 参考图里有没有不该有的元素（球 / 网 / 印刷文字 / 扶球手 / 多余商品 / 型号） | 换干净参考图；不靠后期抹 |
| 3 | 参考图挂上没有（`img[src^="blob:"]` 计数；`thumb-image` 常误报 0） | 重挂，等 6–7s 再确认 |
| 4 | 提示词发出去没有（URL `/chat/` → `/chat/<id>`；长提示词要补发「确认，请直接开始生成视频」） | 补发确认，不重复点发送 |
| 5 | 当前账号额度够不够（开工预检 + 每批前） | 停下列出证据，交人工选切号 / 等次日 / 静态补位 |

> **强制关卡（2026-11-16）**：提交任何视频生成任务**之前**，先把该批次的关键帧 / 首尾帧图发给用户看并取得明确「通过」；未确认不得提交。发图遵守工作区 `AGENTS.md` 的看图成本纪律（先过 `review_sheet.py`、一次一张、不直读原图）。这不是「5 条确定性校验」之一，是它前面的独立人工关卡；额度自动切号不豁免。

> **激活层判定（2026-11-16，用户要求能力化）**：豆包常开**非全屏浮层**（账号/设置下拉、「更多技能」菜单、模型菜单）；此时输入框里可能仍留着提示词，但发送按钮被浮层遮挡，盲点固定坐标会点到设置项，脚本随后在「等生成结果」循环里空等，表现为「卡住且提示词没发出去」。任何点击前先问「当前哪个窗口是激活的」：`ui.mjs:activeLayer(page)` 按 z-index 列出可见浮层；`ui.mjs:sendTarget(page)` 用 `document.elementFromPoint(x, y)` 命中测试，只有发送按钮中心点的最顶层元素就是它自己（或其子元素）才算可点；被覆盖就 `ui.mjs:dismissOverlays(page)` 反复 Escape，仍不通过就停下报告。
>
> **5 分钟硬停（2026-11-16，用户要求）**：非阻塞等待累计超过 5 分钟无进展，立即停脚本 / `job_kill`，写清卡在哪一步与页面状态，交回人工；不重试、不延长 timeout、不反复轮询。`clickSend()` 返回 false 或点击后输入框仍 > 50 字，立即中止，禁止进入等待循环。
>
> **设置弹窗是独立激活窗口（2026-11-16 用户截图）**：`通用 / 豆包账号管理 / 外观 / 通知设置 / 发送按键设置` 居中模态框（遮罩 + 背景模糊 + 右上角 X）打开时，URL 仍是 `/chat/`、提示词仍在输入框，但**当前激活窗口是设置页**；`ui.mjs:activeWindow()` 判为 `settings-modal` 后点它自己的 X 关闭（Escape 常无效），否则打字与发送全部落空。
>
> **两处实测 bug 与修法（2026-11-16，务必照抄）**：①**发送键选择器**——豆包底部「设置齿轮」按钮的 svg class 也含 `size-18`、位置 x≈237、y≈745 比真发送键（x≈1356、y≈728、svg class 含 `send-msg-btn`）更低；若按「y 降序取最底部」会选中齿轮。选择器必须**优先 `/send-msg-btn/`**，`size-18` 兜底时排除 `设置|settings|账号|更多|归档|收起|播报` 且要求 `x > innerWidth/2`。②**关闭弹窗**——设置弹窗的 X 不是 `<button>`（是 svg/div），`activeWindow()` 若只找 `<button>` 会 `close:null`，`dismissOverlays` 点不到 X、Escape 又关不掉 → 卡死。补法：button/role=button/svg/a/div 全找，并加「弹窗右上角 `x+r.width-28 / y+30`」兜底坐标。发送一律用真实 `page.mouse.click(sendTarget.x, sendTarget.y)`，不用 DOM `.click()`。

> 为了拿到确定性，多一次页面判定、一张缩图是应该付的成本；**不为省 token 跳过校验**。

## 二、失败模式 → 回退动作

| 现象 | 回退 |
| --- | --- |
| 模式残留：发了关键帧却回「视频生成参数确认」 | 显式切回图像模式再提交 |
| 额度耗尽「今日视频生成免费额度已用完」 | 失败不扣额度；列出未完成镜头与成本，**交人工选择** |
| 判定误报 `no video`（done 正则漏「你的视频生成好了」） | 开页面人工复查，往往已生成，二次抓取；不直接重跑 |
| 参考图污染（多出球 / 网 / 文字） | 换无该元素的参考图 / 静态补位镜 / 重渲；delogo、inpaint 全糊 |
| 拖拽验证码 `iframe[src*='verifycenter']` | 停下 `handOff()`，交人工 |
| 复合动作只完成一半（撞+倒+鼓包、装+封+举） | 拆镜，一镜只做一件事 |
| 正向提示词里写了 `NO + 具体名词` | 名词会被当成画面元素生成；改成正向描述，删掉整段 `Negative:` |

## 三、边界

- **不确定就停，交人工，不猜。**
- 任何重跑（关键帧 / 视频 / 换提示词 / 换账号）先说明原因与成本，人工确认后才执行。
- 相邻镜衔接以「上镜末帧 + 下镜首帧」两联图判定，drift / mean_abs 只作参考。
- 看图一律先过 [`_shared/scripts/review_sheet.py`](scripts/review_sheet.py)：永不直读 720×1280 / 1080×1920 原图，一次只发一张，动作 `--h 330`、细节 `one --h 900`，超 1000 tokens 降 `--h`。

## 四、按需速查（会崩的地方，不进主路径）

- 图像模式判定看 `Seedream` 模型字样，**不要用 placeholder**（CSS 伪元素不在 `innerText`）。
- 视频规格按钮 `button[aria-haspopup='menu']` 文本 `9:16 · 5s`；比例 / 时长用任务目录 `vid_spec.mjs`，展开菜单要合成 pointer+mouse 事件序列。
- 输入 `[contenteditable="true"]` 用 `ClipboardEvent('paste')`；发送找 svg class 含 `send-msg-btn|size-18` 的**最右** button，**别用坐标点右下角**（会点麦克风触发权限弹窗）；按 Enter 易触发拖拽验证码。
- 下载：滚 `.v_list_scroller-BxcoIX` → 点 `img.cover-u1rIsU` → 取最大 `video.currentSrc` → 页面内 fetch + 分块 btoa → Node 写文件。
- 出片 **5–7 分钟/镜**（不是 2–3 分钟）；图片 25–60s；失败「视频生成失败，生成额度未扣除」不扣额度。
- 账号名正则 `/用户[A-Za-z0-9]+/`（含字母，`\d+` 会漏）；读面板过滤 `y<700`；`taskSpace(<名字>)` 按名字重连，**禁数字**（会过期）。
- 含中文的 `.mjs` / `.json` 一律用 write/edit 工具写（PowerShell GBK 会读坏 UTF-8）；写完校验 U+FFFD=0、JSON `json.load`。
