## 1. 最贵的一课：参考图会「带入」元素

**图里有什么，模型就画什么 —— 包括你不想要的东西。**

`final/K6_box_net_ref.jpg` 里画着一颗静止的球（bbox 约 center≈(500,600)）。S6b v1 与 S7 忠实复制了这颗球，全程静止不动。而 S6a 末帧球已经弹飞出画面 → 白闪转场后观感「球又复活了」，这是整个项目第一轮返工的根因。

**量化**：S6a（`03_clips/S6a_impact.mp4`，4.04s）球在 t=1.6s 后整镜无球；S6b v1 球从 0~4s 全程静止在 bbox(425,536)-(569,687)。

### 防法

1. **用图前逐项检查「图里有什么」**：球、人、文字、型号、多余道具。建议建 `ref_manifest.json` 登记每张参考图的内容。
2. **备一份「无球版」参考图**：`final/K6_box_net_noball.jpg`（从 S6a 末帧 t=2.0 生成，1080×1920，箱歪在顶部压网口、无球、机位一致）。
3. **提示词里写死反向约束**：TRANSIT 规格只给无球版一张参考图 + 写「全程绝对不能出现球」→ 全片 `ballpx=0`。
4. 关键帧出图同理：图里若不该出现品牌字样、绿叶图案，都要在负向词点名。

## 2. 后期抹球：三条路全部走死（别再试）

球压在「箱角 + 网绳 + 背景」三种材质交界，且横跨画面中部（x 425–569，画面宽 720）：

| 手段 | 命令 / 参数 | 结果 |
| --- | --- | --- |
| ffmpeg delogo | `delogo=x=410:y=522:w=172:h=178` | 糊成横向拉伸斑块 |
| cv2 inpaint | TELEA / NS（opencv-headless 5.0.0；中文路径需 PIL 读再转 cv2） | 更大放射状糊斑 |
| 裁剪 | — | 球在画面中部，裁不掉 |

**唯一干净解**：换天然无球的参考图重新生成，或改用静态补位镜（下 §4）。
**推论**：涉及商品/道具的「多出来 / 少掉」问题，优先在**输入侧**（参考图 + 提示词）解决，不要投入后期修补。

## 3. 衔接判定：以两联图为准，像素差只作参考

- **工具**：`_shared/scripts/review_sheet.py pair <上镜视频> <下镜视频> --h 620`（约 624 tokens；**只接受视频输入**，传静态图会报 `UnidentifiedImageError: cannot identify image file`）。
- **口径**（工作区 AGENTS.md 强制）：动作推进型末帧（车驶远、物件已飞离）与静态关键帧差异天然很大，但衔接可成立。`drift` / `mean_abs` **只作参考，不作返工依据**；S7 首末帧 `mean_abs_diff=18.4`（网绳余振）属预期内。
- **客观门槛（11-13 新增）**：用户自拼两段的硬切点帧间差异 **45.4**，其余帧仅 7–10 → 可把「**硬切处帧间差异 < 15**」当作能否直接硬切的辅助门槛（仍以两联图目检为准）。
- 上一镜结束状态 = 下一镜起始状态；出片后必抽末帧与下镜首帧做两联对比。

## 4. 补救工具箱（按性价比排序）

### 4.1 静态补位镜 ★ 零额度、最常用

用**上镜末帧**做一张静态图，加极缓 zoompan，顶掉一条出问题的视频。

```bash
ffmpeg -loop 1 -i <上镜末帧.png> -t 2 \
  -vf "scale=720:1280,zoompan=z='min(zoom+0.0004,1.04)':d=1:...:s=720x1280:fps=30" \
  -c:v libx264 -pix_fmt yuv420p 03_clips/S6b_static_hold.mp4
```

- 产出 130KB / 2s / 60 帧 / 720×1280 / 30fps；1.04x 微推不显死板。
- 用途：S6b 重渲两版仍不对（v3 球没了但箱子在开头 1 秒被「扶正」并右移），改用 S6a 末帧静态补位 → 无球、斜箱始终压网口、与 S6a 衔接顺滑。
- 开箱揭示镜同理：`03_clips/S10open_reveal.mp4`（2.5s / zoompan 1.05x），把静态关键帧做成微推视频，不耗额度。

### 4.2 桥接过渡镜（TRANSIT）★ 解决「两段独立生成机位对不上」

两条独立生成的视频，机位/景别天然不同（S6a 低机位近景箱墙满画面 vs S8 机位退远箱墙变小），硬切必然跳。

**正确做法**：用**前一镜末帧**做新镜的唯一首帧参考，生成一条「桥接镜」，让机位变化由新镜头自身演掉。

- `03_clips/TRANSIT_boxfly.mp4`（720×1280 / 24fps / 4.04s），规格 `.egotasks/video_spec_transit.json`，唯一参考图 `final/K6_box_net_noball.jpg`。
- 首帧与 S6a 末帧的箱子角度/位置/箱墙大小几乎完全重合 → **无需白闪**；自含完整「脱网 → 朝镜头飞来变大 → 箱盖掀开露米白纸丝」→ 因此直接删掉 S8。
- 会话 https://www.doubao.com/chat/38453753826297090

### 4.3 0.1s 白闪硬切

机位有小幅差异但不值得重渲时（S6a→S6b 箱墙可见 3 列→2 列），用户决策「0.1s 白闪硬切，不重渲」。S3→S4 / S5→S6a 也用过 0.1–0.15s 白闪。

### 4.4 删镜也是合法补救

S7 全程带一颗抹不掉的球 → 直接从 A 轨删除；S8 被 TRANSIT 取代。**不要为了「凑够镜数」保留有硬伤的镜头。**

### 4.5 末帧定格收尾

```bash
# 4s 封口 + 1.5s 末帧定格 = 5.54s
[1:v]scale=720:1280,fps=24,trim=0:1.5  +  concat n=2
```

- 抽末帧用 `-ss 4.0`（`-sseof` 在 Windows 下报 `Error opening input file ...\_s10b_last.png`）。
- **音频必须同步**：silence 长度 = FREEZE_T + HOLD = 4s，否则音轨短一截（曾出现 27.4s 对不上画面）。
- 用途：补「成品展示」收尾、避免 AI 取出商品时悬浮穿帮。

## 5. 参考图预处理

| 问题 | 处理 |
| --- | --- |
| 模型出图顶部有纯色黑边 | `K6_box_net.jpg` 顶部 **119px**（RGB 22,36,36）、`K6a_incoming.png` 约 **134px** → `scripts/trim_k6_ref.py` / `trim_top.py`（`TRIM_TOP_PX=134`）裁掉再生成 `final/K6_box_net_ref.jpg`(1080×1920) |
| 生成图底部有「豆包 AI 生成」水印 | 裁底部 **110px / 6.2%** 后按 cover 缩放到 1080×1920（PIL：crop 底部 → `max(TW/w,TH/h)` 缩放 → 居中裁） |
| 水印位置会跳 | 右下常驻、结尾闪左上；`经验_豆包去水印提示词.md` 已证伪「提示词写 TikTok」方案；真要去只能 LaMa inpaint（3s/帧，全片 40–80 分钟）或客户端导出。本工作区最终**保留水印直接交付** |
| 参考图带型号文字 / 尺寸标注 | 从商品图裁掉顶部 100px 型号文字 + 底部 140px 尺寸标注 → `02_keyframes/clean_refs/`（759×784 无文字） |
| **商品实拍尺寸图要随参考图一起给** | 快递袋 **35×25cm 侧边 5cm / 100 片一捆**，小熊挂饰 **7.5–8.5cm / 60–82.5g**；不给尺寸图，模型会把袋子画得比小熊还小 |
| **不支持上传参考视频** | 豆包 file input accept 只含图片/文档/音频，无 mp4。实拍视频（如 `VID20261110101310.mp4` 1440×1440）只能抽关键帧图片当参考：`act_r1_lift` / `act_r2_insert` / `act_r3_peel` / `act_r4_fold` / `act_r5_press` / `act_r6_done`，存 `02_keyframes/S9_kd/` |

## 6. 商品锚点卡：写错一次占 40% 工期

- 真实包装写**最前面**（三款小熊铁律：每只各装一只透明 PE/OPP 自封袋、一只一袋、无礼盒无盲盒无棉纸；袋薄膜软有褶皱反光、封口有白色自粘胶条）。
- 具名锚点含颜色 hex、配件形状/材质、可数元素；配色表主色+辅色+禁止色；禁止项点名具体物体；K8 出图后逐条对照白底图。
- `2026-11-13_世界杯点球盲盒/00_input/product_anchor.md` 至今仍是空模板（SKU 01/02 占位），是 B 轨早期 blocked 的原因 —— **新任务开工第一天就要填满**。

## 7. 复刻不是「抄几个画面」，是「抄画面逻辑」（2026-11-16 兵马俑送礼任务血泪）

**用户原话（m01377）：「复刻不只是看几个画面，要理解画面逻辑」。**

上一节「用参考图锁站位」只解决了**几何**（谁站哪、多大、什么朝向）。但真正决定「像不像原片、好不好看」的是**画面逻辑**——每一拍为什么这样拍、为什么是这个时长、为什么是这个人物的这个反应。只锁站位而丢了逻辑，成片会「构图对了但味道全错」。

### 复刻前必须先写的「画面逻辑卡」（逐段，开拍前完成）

对原片（或任何要复刻的参考片）逐段回答五个问题，写进 `01_plan/画面逻辑.md`：

1. **这一段在讲什么**（叙事功能）：建立？铺垫？爆点？消解？例如原片 A 段=建立「女孩敢跟雕像玩石头剪刀布」的日常感，不是「展示猜拳动作」。
2. **观众的注意力在哪**（视觉中心）：原片固定机位、女孩偏左背影、俑在右——注意力始终在「女孩的手 vs 俑的静止」这条对峙线上。构图必须保护这条线，任何多余人物/道具抢戏都是错的。
3. **这一拍的情绪目标**（观众应产生什么感受）：B 段那 4.5 秒静止空拍=「要出事了」的悬（suspense），不是废镜头。删掉它=删掉原片 90% 的味道。
4. **节奏/时长为什么是这个值**（测量式依据）：B 段 4.5s 是吊胃口的最小可信长度；A 段多拳高频才有「一次次出拳」的推进感，只出一拳就假。用 `原片节奏测量.md` 的差分曲线校准，不靠肉眼估。
5. **与下一段的因果钩子**（衔接逻辑）：A 段「俑纹丝不动」→ 才有 B 段「突然对手不动」的疑 → 才有 C 段「突然动了」的惊。三段是**因果链**，不是三个并列动作。

### 两条硬教训（本项目实际翻车点）

- **别把「画面」当主体，把「逻辑」当附件**：本项目出关键帧时反复要求「S2 女孩要走到中间俑前」——但一开始只写文字描述站位，模型自由发挥，站位全错；后来每一镜都拿**原片对应帧/上一镜定稿帧**当构图参考图才锁住。**几何靠参考图锁，逻辑靠画面逻辑卡锁，二者缺一不可。**
- **时长/节拍是逻辑的一部分，不是后期随便剪**：B 段静止空拍若被压到 1s，观感立刻从「悬疑」变「卡顿」。生成每条视频前先确认它对应原片哪一段、那一段的时长依据是什么。

### 自检（渲染后回测量）

- 用同一套差分脚本跑我方成片的每一段，对照原片 A/B/C 曲线形状：A 高频锯齿、B 明显低谷(<1.5)、C 单峰爆发。形状对不上=画面逻辑没复刻到位，返工该段而不是补几个帧。
