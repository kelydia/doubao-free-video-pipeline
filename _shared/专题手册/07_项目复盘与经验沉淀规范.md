# 项目复盘与经验 / SOP 沉淀规范（跨任务强制）

> 用户 2026-11-16 11:17：「统一工作区中的项目，项目经验、SOP 可以复用的都独立出来，每个项目完成后，都自动进行复盘，提取可复用的经验、sop 合并更新到工作区的文件中」。
> 标准：**简约、直接、稳定** —— 稳定 > 省 token > 省时间；「稳 vs 省」不预设规则，交人工。
> 唯一权威三件套：本规范（规则）· [`../复用资产登记.md`](../复用资产登记.md)（台账）· [`../scripts/project_retro.py`](../scripts/project_retro.py)（机械层）。
> 与全局 `~/.dsh/AGENTS.md`「任务结束必写 `任务总结.md`」并列：**总结是记录，复盘是提取**，两步都要做。

---

## 一、触发点（「自动」= 无需用户提醒）

任务进入任一状态即执行：成片交付 / `update_goal(complete)` / 用户确认完结 / 一次返工修复验收通过。

顺序：`任务总结.md` → 下面四步 → `python _shared/scripts/project_retro.py --apply`。

重跑、切号、补渲不算新项目，但**修复结束仍要补一条复盘记录**（2026-11-16 球消失返工就是教训：成片交付后才发现验收漏了 `joins["S3","S4"].must_match`）。

## 二、四步

1. **复盘**：在 `任务总结.md` 写「经验教训 + 工作流优化建议」，只写事实（现象 / 根因 / 代价 / 防法），不写感想。
2. **判定可复用**：三条**同时满足**才「独立出来」：
   - 与具体商品 / 主题 / 任务路径**无耦合**（能参数化）；
   - 至少 2 个项目遇到，或明确会阻断下一任务；
   - 已经验证有效，不是猜测。

   任务专用脚本、一次性实验脚本**不物理搬运**，只在台账 C 表登记索引 —— **不制造多份真相**。
3. **合并更新**：按下表写入**已有文件**，只追加或改对应段落，不新建平行文档。

   | 类型 | 合并去向 |
   | --- | --- |
   | 硬规则 / 强制关卡 | 工作区 `AGENTS.md`（唯一一处；改前确认无并行编辑，有冲突就先记台账「待并入项」） |
   | 主干流程 / 开工检查 | [`../工作流_SOP.md`](../工作流_SOP.md) |
   | 浏览器操作确定性校验 | [`../豆包网页版操作手册.md`](../豆包网页版操作手册.md)（唯一权威最小 SOP） |
   | 提示词 / 参考图 / 衔接 | [`01_提示词与动作设计.md`](01_提示词与动作设计.md)、[`02_参考图_衔接与补救.md`](02_参考图_衔接与补救.md) |
   | 音频 / 合成 | [`03_音频与合成.md`](03_音频与合成.md) |
   | 工程环境 / 账号额度 | [`04_工程环境_编码_账号.md`](04_工程环境_编码_账号.md)、[`05_账号轮换与额度自动切换规范.md`](05_账号轮换与额度自动切换规范.md) |
   | 可复用模板 | [`../templates/README.md`](../templates/README.md) + 对应模板目录 |
   | 可执行脚本 | [`../scripts/`](../scripts/project_retro.py) |

   **同一经验只写一处**；旧文档里的过时状态标「已并入 XXX」，不留两份互相矛盾的说法。
4. **登记**：台账人工区加一行（项目 / 完成日 / 结论出处 / 合并去向 / 状态），再跑 `project_retro.py --apply` 刷新 AUTO 区块。

## 三、分工（诚实边界）

| 谁 | 做什么 | 不做什么 |
| --- | --- | --- |
| `project_retro.py` | 扫项目、查总结与台账、列已独立资产与散落候选、幂等重写 AUTO 区块 | 不判断经验价值、不改 SOP、不搬文件、不删文件 |
| 收尾 agent | 语义复盘、判定可复用、合并进目标文件、写台账人工区 | 不跳过第 1 步直接改 SOP |
| 用户 | 「稳 vs 省」取舍、重跑确认、关键帧确认 | — |

> 没有可靠的无人值守 LLM 钩子，所以「自动」是**流程强制 + 机械检查全覆盖**，不是后台守护进程。脚本保证「不会漏掉某个项目没复盘」，语义判断由收尾 agent 完成。

## 四、自检（收尾逐条过）

- [ ] 台账人工区有本项目一行；`project_retro.py --json` 的 `need_retro` 不含本项目。
- [ ] 每条新经验只有一个权威落点，旧状态已标注。
- [ ] 没有物理搬运正在被使用的任务脚本。
- [ ] 改过的 `.md` / `.mjs` / `.json` 的 U+FFFD = 0；Markdown 链接目标存在。
- [ ] 未完结的返工在台账标「进行中」，完结后补记录。

## 五、禁止

- 禁止每个任务重写一份 SOP / 新建平行手册：**要合并，不要堆叠**。
- 禁止把「脚本跑通」当成「已复盘」；台账人工区没写就不算。
- 禁止为省 token 跳过复盘；这是稳定成本，不是优化项。
- 禁止把「稳 vs 省」写成自动规则（多耗额度拿真视频 / 0 额度静态补位镜等），一律准备证据后交人工选择。
