## 1. 图像 / 视频模式会残留（11-15 最大的新坑）

**`freshChat()` 只开新对话，不会切换「视频生成 / 图像生成」模式。** 页面停留在上次的模式，豆包会把「生成关键帧」理解成「生成视频」，反复回「视频生成参数确认：模型 Seedance 2.0 Mini、时长 15 秒…确认后我再开始生成视频」。

**解法**：写独立脚本 `gen2_img.mjs`（放 `D:/ProgramData/ego-tasks/penalty-box-20261113-2113/`），流程：

1. `goto /chat/` → 等 6s → `Escape` 关弹窗。
2. 找 `<button>` 文本「图像生成」（约 @(864,780) 或 @(671,780)，随布局变），`mouse.move + click`。
3. **判定图像模式**：以「比例」控件 + `Seedream` 模型出现为准。**不要**用 placeholder 判定（是 CSS 伪元素，不在 `innerText`）。
4. `typeInto` → `attach(refs)` → `clickSend`。
5. 轮询**只认 `img[src*="rc_gen_image"]` 计数 > before**；**忽略 `blob:` 缩略图**（那是参考图，`blobimgs 2` 是误报）。
6. `fetch` 只取 http(s) 的 `rc_gen_image` URL；返回 **PNG 字节**，扩展名写 `.jpg` 会报格式不匹配。

**踩坑记录**：早期版本把 `blob:>0` 当成功 → `fetch(blob:)` → `TypeError: fetch failed` 脚本崩，且该会话其实并未出图。

## 2. 编码：中文 .mjs / .json 一律用 write / edit 工具

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| PowerShell `Set-Content -Encoding UTF8` | 把 UTF-8 中文按 GBK 读坏，`BASE` 行全乱 → `SyntaxError: Invalid or unexpected token` | **含中文的 .mjs / .json 一律用 write / edit 工具写，禁 PowerShell 读写** |
| `json.dump` / `Set-Content` 带 BOM | `SyntaxError: Unexpected token ''` | 用 `[System.IO.File]::WriteAllText(path, json, (New-Object System.Text.UTF8Encoding $false))` 或 write 工具；**写完必须 `json.load` 校验** |
| 半角 `"` 出现在中文提示词里 | `SyntaxError: Expected ',' or '}' after property value in JSON at position 450` | 中文引号一律用「」 |
| 中文文档被 GBK 重写 | 出现替换字符（「圣□□小熊」） | 写后 `open(...,encoding='utf-8')` 校验 `t.count(chr(0xFFFD))` 必须为 0；修复用 `t.replace("六、圣\ufffd\ufffd小熊","六、圣诞小熊")` |

**读中文文件**：用 `ops_read_files` / `ops_inspect_local_file` / `read`，不用 `Get-Content`。

## 3. 路径：纯 ASCII 入口

用户目录 `C:\Users\李爱华` 含非 ASCII，而 `ego-browser nodejs -e` 的入口参数必须纯 ASCII。

```
脚本目录：D:/ProgramData/ego-tasks/<任务名>-<YYYYMMDD-HHmm>/
入口：ego-browser nodejs -e "await import('file:///D:/ProgramData/ego-tasks/<任务目录>/round-XX.mjs')"
```

- 脚本内容（含中文）写在 `.mjs` 文件里，**绝不放进 `-e` 参数**。
- 每轮写一个新文件（`round-01.mjs`、`round-02.mjs`…），不要改旧文件重放。
- 脚本内一律用**绝对路径**（ego 的 node cwd 在 `C:\Program Files\Citro Labs\ego lite\...`）；参数走 `args.txt`。
- 结束按规范 `task.finish({ keep: [] })`。
- 任务结束时若任务空间被回收，用 `claimTaskSpace(0)`，**不要** `takeOverTaskSpace`。
- **不要用 `C:\ProgramData\ego-tasks`**（已移除，统一 D 盘）。

## 5. vid.mjs 的 done 检测不可靠 → 人工复查 + 二次抓取

- 豆包完成语有变体（「你的视频生成好了。」），早期 wait 正则漏匹配 → 脚本报 `no video`，但页面其实已生成好。
- 另一次报 `videos:[]` 是因为需**滚动 + 点封面**才加载 `<video>`。
- **标准应对**：报 no video 时不要直接判失败重跑（可能白耗额度）→ 人工打开会话页 → 确认「你的视频生成好了」→ 用 `grab.mjs` 二次抓取（滚底 `.v_list_scroller-BxcoIX` → 点 `img.cover-u1rIsU` → 取最大 `video.currentSrc` → fetch 分块写文件）。
- **出片耗时实测 5–7 分钟**（不是文档早期说的 2–3 分钟 / 60–170s）；图片约 25–35 秒/次。>10 分钟无响应（页面停「大约需要 1-3 分钟」）才判失败重提。
- 时长滑块最小 **4s**、最大 **15s**；`vid.mjs` 下拉偶尔没吃准（要 3s 给 4s），4s 全片可用，不必纠结。
